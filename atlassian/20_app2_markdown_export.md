## 4. Границы v1

### Входит

1. Экспорт **страницы**, **страницы с потомками** (вся глубина) и **всего пространства**.
2. **Порядок** как в дереве Confluence: числовые префиксы (`010-`, `020-`) или `_index.md` —
   выбрать в плане, сделать настраиваемым, если дёшево.
3. **Имена файлов:** транслитерация диакритики, кириллицы; CJK — транслит или безопасный slug
   с id; уникальность при совпадении заголовков.
4. **Стабильные пути:** путь страницы не меняется между выгрузками, пока не переименована
   или не перемещена; при переименовании — предсказуемое правило (решить в плане).
5. **Front-matter** (YAML): id, title, space, parent id, версия, автор последней правки,
   дата, метки, исходный URL.
6. **Переписывание ссылок** между страницами на относительные пути и **вложения/изображения**
   с относительными путями — это сильная сторона лидера, повторить обязательно.
7. **Инкрементальный экспорт:** только страницы, изменённые с прошлой выгрузки, + список удалённых.
8. **Манифест выгрузки** (`export-manifest.json`): что, когда, какие версии, какие пропущены и почему.
9. Конвертация storage format → Markdown: заголовки, списки, таблицы, код, панели/инфо-макросы
   (в blockquote или admonition), изображения, ссылки, упоминания. Неизвестные макросы —
   не терять молча: заглушка + запись в манифест.
10. Результат — **zip, скачиваемый файлом** из Custom UI (Blob + `<a download>`, как CSV в Trace).
11. Лицензия: ≤10 пользователей бесплатно; проверка `license.active` в резолвере и во фронте.
12. 26 языков интерфейса, светлая/тёмная тема — как в Trace.

### Не входит в v1

- Расписание и **push во внешний git** — это egress, он убивает Runs on Atlassian и 100%
  ревшары. Пользователь сам кладёт zip в git или в CI.
- Импорт Markdown в Confluence, двусторонняя синхронизация.
- Экспорт в другие форматы (HTML, PDF, DOCX).
- Confluence Data Center.

## 5. Жёсткие требования платформы

Из [02](02_forge_implementation.md) §1.1–1.2 и опыта Trace — не обсуждаются:

- Только Forge, ноль Connect-модулей, **ноль egress** → Runs on Atlassian (проверять
  `forge eligibility -e development --non-interactive` на каждом деплое).
- Custom UI: React 18 + Atlaskit + design tokens, всё бандлить (никаких CDN и внешних шрифтов),
  `permissions.content.styles: unsafe-inline` для Atlaskit, как в Trace.
- **Полный набор scopes заявить в v1** — добавление scope позже = мажорная версия и
  повторное согласие клиентов (ловушка из Trace). Только чтение: приложение в Confluence не пишет.
- Не хранить персональные данные (account id и т.п.) дольше, чем нужно для выгрузки — как
  TRACE-30. Автора в front-matter брать в момент экспорта, не хранить.
- Лимиты: резолвер 25 с, async-очередь до 900 с, память до 1 024 МБ, ответ на фронт 5 МБ,
  запрос с фронта 500 КБ, `/tmp` 512 МБ, 7 000 вызовов/мин на инсталляцию.

## 6. Архитектура: развилка, которую решает G4

Главный вопрос — **где собирать zip из 1 000 страниц**, если ответ на фронт ограничен 5 МБ.

| | A: сборка в браузере | B: сборка на бэкенде |
|---|---|---|
| Как | Custom UI сам запрашивает страницы через `requestConfluence` из `@forge/bridge` (от имени пользователя), конвертирует и пакует zip в браузере (JSZip или аналог, в бандле), отдаёт Blob | consumer очереди (900 с) выгружает и конвертирует, складывает части в хранилище Forge, фронт забирает частями и склеивает |
| Плюсы | нет лимита 5 МБ, нет 900 с, права — ровно права пользователя, почти нет хранения | работает при закрытой вкладке |
| Минусы | вкладку нельзя закрывать; скорость зависит от браузера и rate limit | хранение больших файлов в KVS дорого и ограничено; сборка по частям сложна |
| Гипотеза | **предпочтителен** — проверить на 1 000 страниц с вложениями | запасной |

Инкрементальность в обоих вариантах: карта `page id → {version, path}` последней выгрузки
в Forge SQL или KVS (на пространство и на пользователя — решить в плане), без содержимого страниц.

Ядро — **чистые функции без I/O** (конвертер storage→Markdown, планировщик путей, транслит,
front-matter, переписывание ссылок, дифф для инкремента), покрытые тестами. Хендлеры — тонкие.
