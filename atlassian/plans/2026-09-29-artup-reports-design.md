## 1. Что строим

Выгрузка задач Jira Cloud — из поиска, доски, бэклога, спринта, одной задачи или своей страницы — в
форматированный .xlsx, .docx по шаблону и PDF. Файл собирается в браузере пользователя, данные не
покидают Atlassian (Runs on Atlassian, ноль egress). Ключ `com.artuplabs.reports`, код — `apps/reports`
в этом репозитории, коммиты `REPORTS-<n>: <Description>`.

Решения владельца (брейншторм 2026-09-29):

| Вопрос | Решение |
|---|---|
| Форматы v1 | Excel + Word + PDF |
| Шаблоны | встроенные + свой .docx с плейсхолдерами |
| Права на шаблоны | личные у каждого; проектные публикует админ проекта; сайтовые — админ Jira |
| Архитектура | сборка в браузере (v1); ядро — чистые функции, переносимые на бэкенд Forge для расписания в v1.1 |

## 2. Архитектура

Всё чтение Jira и сборка файла — в Custom UI через `requestJira` (`@forge/bridge`) от имени пользователя.
Резолвер Forge отдаёт только шаблоны и лицензию, поэтому лимиты резолвера (25 с, 5 МБ ответа) не
касаются выгрузки. Всё, что ниже `export/pipeline`, не знает, где исполняется.

| Модуль | Что делает | Зависит от |
|---|---|---|
| `core/query` | JQL / фильтр / доска / спринт → id страницами по 5 000 → пачки по 100 | — |
| `core/fields` | каталог полей Jira → типизированные значения (дата, число, пользователь, ссылка, ADF) | — |
| `core/adf` | ADF → нейтральная модель документа (§4) | — |
| `core/text-runs` | разбивка текста по письменности: латиница/кириллица ↔ CJK ↔ хангыль | — |
| `core/filename` | имя файла по шаблону `{project}-{date}-{filter}` | — |
| `render/xlsx` | модель → .xlsx: типы, гиперссылки, закреплённая шапка, автофильтр, ширина колонок, листы по группировке, лист «Сводка» | exceljs 4.4.0 |
| `render/docx` | модель + встроенный шаблон → .docx: повтор шапки таблиц, колонтитулы, картинки | docx 9.8.1 |
| `render/pdf` | модель + встроенный шаблон → PDF; шрифты Noto Sans (в бандле), Noto Sans SC / KR — лениво, только если в выгрузке есть такие символы | pdfmake 0.3.11 |
| `render/docx-template` | свой .docx пользователя → .docx (§5) | docxtemplater core (MIT) |
| `export/pipeline` | чтение с конкурентностью (bulkfetch ×6, вложения ×12), повтор 429/5xx, прогресс, отмена | `@forge/bridge`, образец — `apps/export` |
| резолвер `templates` | CRUD шаблонов, проверка прав через `asUser()` | Forge KVS, `@forge/api` |
| UI | мастер экспорта, управление шаблонами, 26 языков, светлая/тёмная тема | Atlaskit, токены, i18n из Export |

Библиотеки рендера грузятся динамическим импортом по выбранному формату (каждая ~1 МБ).
У exceljs уязвимая зависимость `uuid` закрывается через `overrides`.

### Порядок чтения (замерен в X-G5)

1. `POST /rest/api/3/search/jql` — только id, `maxResults: 5000`, по `nextPageToken`.
2. `POST /rest/api/3/issue/bulkfetch` — по 100 задач, 6 параллельно, только поля шаблона.
3. Комментарии, ворклоги, подзадачи, связи — только если шаблон их использует; пачками, той же конкурентностью.
4. Вложения-картинки (Word/PDF) — конкурентность 12 и выше; картинки держатся потоком, не копятся всем документом.

## 3. UX

### Точки входа

Все шесть модулей открывают один мастер; различается только начальный JQL.

| Модуль | Начальный JQL |
|---|---|
| `jira:issueNavigatorAction` | текущий JQL поиска |
| `jira:boardAction`, `jira:backlogAction` | JQL фильтра доски |
| `jira:sprintAction` | `sprint = <id>` |
| `jira:issueAction` | `key = <KEY>` |
| `jira:globalPage` | пусто: ввод JQL или выбор сохранённого фильтра |

`globalPage` содержит две вкладки: «Экспорт» (мастер) и «Шаблоны».

### Мастер — три шага

1. **Формат и шаблон.** Карточки Excel / Word / PDF → список шаблонов (встроенные, личные, проектные,
   сайтовые). Excel: выбор и порядок колонок перетаскиванием, группировка по полю на листы, лист
   «Сводка» (счёт по статусу, исполнителю, приоритету) вкл/выкл. Word/PDF: скриншот шаблона, размер
   бумаги A4 / Letter.
2. **Предпросмотр.** Только для Excel: первые 5 задач так, как они будут в файле; сверху JQL и число задач.
3. **Выгрузка.** Прогресс по фазам (чтение → картинки → сборка), отмена, итог «N задач за M с»,
   предупреждения (элементы, выведенные текстом; недоступные картинки), «Скачать» и «Скачать ещё раз»
   (Blob + `<a download>`, как в Export).

Каждый файл несёт JQL, время, автора выгрузки и число задач: Excel — в свойствах документа и на листе
«Сводка», Word/PDF — в колонтитуле первой страницы.

### Вкладка «Шаблоны»

Списки «Мои» и «Общие» (проектные и сайтовые). Создание Excel-шаблона — тот же выбор колонок, что в мастере.
Загрузка .docx — перетаскиванием, с проверкой при загрузке (§5). Шаблон с ошибками сохранить нельзя.

## 4. ADF → модель документа

| ADF | Узел модели | Word / PDF |
|---|---|---|
| paragraph, heading 1–6, text с метками (strong, em, code, link, strike, underline, textColor) | `Para{runs}`, `Heading{level}` | как в Jira |
| bulletList, orderedList (вложенные) | `List{ordered, items}` | настоящие списки Word |
| table (colspan, rowspan, строка заголовка) | `Table{rows, cells{colspan,rowspan}}` | объединённые ячейки сохранены, шапка повторяется на каждой странице |
| codeBlock, blockquote, panel, rule, expand | `Code`, `Quote`, `Panel{kind}`, `Rule`; expand → заголовок + содержимое | моноширинный шрифт; панель — рамка с заливкой |
| mediaSingle, mediaGroup | `Image{attachmentId}` | картинка, вписанная в ширину страницы |
| mention, emoji, date, status, inlineCard | текстовые куски | «@Имя», символ эмодзи, дата в локали, «[СТАТУС]», ссылка |
| неизвестный узел | текст узла | предупреждение `adf-fallback` со счётчиком в итоге |

Excel получает ту же модель простым текстом с переносами строк; текст длиннее 32 767 символов
обрезается с пометкой в конце ячейки.

Картинка в ADF ссылается на id медиа-сервиса, а не на id вложения. Сопоставление — по имени файла со
списком вложений задачи; запасной путь — ссылки `/attachment/content/{id}` в `renderedFields`.

## 5. Свой .docx-шаблон

Движок — ядро docxtemplater (MIT): склеивает плейсхолдеры, которые Word разрезал на несколько `w:r`,
понимает циклы, условия и вставку готового XML. Поверх ядра — свой код:

- **Богатые поля** `{{@description}}`, `{{@body}}`: модель §4 → OOXML (таблицы, картинки, форматирование; списки — абзацами с отступом и маркером, `numbering.xml` шаблона не трогается).
- **Картинки**: файлы добавляются в `word/media/`, связи — в `word/_rels/document.xml.rels`, типы — в
  `[Content_Types].xml`. Платный модуль картинок не нужен.

Синтаксис:

| Что | Как |
|---|---|
| поле задачи | `{{key}}` `{{summary}}` `{{status}}` `{{assignee}}` `{{priority}}` `{{due}}` `{{created}}` … |
| своё поле | `{{field "Story Points"}}` (по имени) |
| богатое поле | `{{@description}}` (в задаче), `{{@body}}` (в `{{#comments}}`), `{{@comment}}` (в `{{#worklogs}}`); тот же тег без `@` даёт простой текст |
| цикл по задачам | `{{#issues}}…{{/issues}}`; внутри строки таблицы повторяет строку |
| вложенные циклы | `{{#comments}}` `{{#subtasks}}` `{{#worklogs}}` `{{#links}}` |
| условие | `{{#assignee}}…{{/assignee}}` — секция с непустым значением выводится один раз, с пустым — пропускается |
| сведения о выгрузке | `{{jql}}` `{{exportedBy}}` `{{exportedAt}}` `{{count}}` |

Проверка при загрузке: неизвестное поле → «Найден `{{summry}}` — имели в виду `{{summary}}`?»;
незакрытый цикл или условие → имя тега и пояснение. Шаблон — не больше 2 МБ.

## 6. Встроенные шаблоны (8)

| Формат | Шаблоны |
|---|---|
| Word и PDF | одна задача; список задач; отчёт по спринту; релиз-ноуты |
| Excel | список задач; ворклоги (строка на ворклог); комментарии (строка на комментарий); итоги спринта |

Каждый снимается скриншотом на A4 и Letter, в латинице, кириллице и CJK — без обрезаний.

## 7. Хранение шаблонов и права

Forge KVS:

- `tpl:{scope}:{scopeId}:{id}` — метаданные: имя, формат, колонки/группировка (Excel) или список
  плейсхолдеров, автор, даты, число частей файла. `scope` ∈ `user` | `project` | `site`.
- `tplbin:{id}:{n}` — файл .docx частями по 150 КБ, в base64 ≈ 200 КБ (значение KVS ≤ 240 КБ); до 14 частей = 2 МБ.
  Загрузка и чтение — по части на вызов резолвера.

Содержимое задач не хранится нигде.

Права проверяет резолвер (`asUser()` → `GET /rest/api/3/mypermissions`), не фронт:

| Действие | Личный | Проектный | Сайтовый |
|---|---|---|---|
| видеть, использовать | автор | BROWSE_PROJECTS в проекте | все пользователи |
| создавать, менять, удалять | автор | ADMINISTER_PROJECTS в проекте | ADMINISTER |

## 8. Ошибки

| Ситуация | Поведение |
|---|---|
| 429, 5xx, сетевой отказ | повтор с `Retry-After`, иначе экспоненциальная пауза; до 6 попыток; AbortError не повторяется |
| пачка не прочиталась после повторов | экран ошибки, «Повторить недостающее» дочитывает только упавшие пачки. Неполный файл отдаётся только отдельной кнопкой: имя с суффиксом `-PARTIAL`, в файле баннер «N из M задач» |
| картинка 403 / 404 | рамка «картинка недоступна», счётчик в итоге |
| отмена | `AbortController` на всех запросах, ссылки на данные сбрасываются |
| Word/PDF больше 2 000 задач | отказ до чтения: «Сузьте JQL или выберите Excel» |
| Excel | без предела; 50 000 задач — с прогрессом, без падения вкладки |
| ошибка JQL | текст ошибки Jira рядом со строкой ввода |
| один проблемный узел или задача | ловится на уровне задачи; задача выводится с пометкой, выгрузка не прерывается |

## 9. Лицензия

Ступень Marketplace «бесплатно до 10 пользователей»: без водяного знака и без ограничений функций.
`license.active` проверяют фронт (`view.getContext()`) и резолвер. Без активной лицензии экспорт
заблокирован, экран со ссылкой на пробную версию и покупку; урезанного режима нет.

## 10. Тесты и приёмка

- **Модульные тесты (vitest), ядро:**
  - `core/adf` на фикстурах из реальных задач RPT: объединённые ячейки, CJK, вложенные списки, картинки.
  - `render/xlsx`: файл читается обратно exceljs; проверяются типы ячеек, гиперссылки, закреплённая
    шапка, автофильтр, листы группировки, «Сводка».
  - `render/docx`, `render/docx-template`: распаковка и проверка XML; отдельные случаи для
    плейсхолдеров, разрезанных на несколько `w:r`, для вложенных циклов и картинок.
  - `render/pdf`: снимок описания документа pdfmake и разбивка на шрифты.
  - `core/text-runs`, `core/filename`, `core/query` (пагинация, пачки).
- **Резолвер:** CRUD шаблонов, части файла и вся матрица прав §7 на замоканном `@forge/api`.
- **Приёмка на artuplabs-dev (проект RPT), по §4 брифа:**
  - 10 000 задач в .xlsx за ≤ 60 с в браузере;
  - 500 задач с картинками в .docx и PDF за ≤ 120 с каждый;
  - 8 встроенных шаблонов × A4/Letter × латиница/кириллица/CJK — скриншоты без обрезаний;
  - пик памяти вкладки;
  - 50 000 задач в .xlsx — на синтетических данных прямо в ядре, без сети.
- Приёмка владельцем в браузере — чек-лист `2026-09-29-artup-reports-acceptance.md`, как в Export.

## 11. Первые проверки плана

До основной работы, в первой задаче плана:

1. Конкурентность вложений 12 через `requestJira` из браузера без 429 (R-X5); иначе запасной путь —
   `/rest/api/3/attachment/thumbnail/{id}`.
2. Сопоставление медиа ADF с вложениями задачи по имени файла на задачах RPT.
3. Лицензия docxtemplater core — MIT: **проверено** 2026-09-29 (`npm view docxtemplater license` → MIT, 3.71.0; pizzip — MIT OR GPL-3.0, берём MIT).
4. Точный лимит значения Forge KVS и размер полезной нагрузки `invoke` — для частей шаблона.

## 12. Не входит в v1

Расписание и рассылка (v1.1: Forge scheduled trigger + вложение файла в задачу), импорт из Excel, Jira
Data Center, PowerPoint, PDF/A, предпросмотр Word/PDF на данных задач.
