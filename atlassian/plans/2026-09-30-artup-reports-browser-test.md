## Дефекты

### D1 — пример имени файла без `{project}` (мелкий) — исправлен в 3.4.0
Навигатор и глобальная страница с `project = RPT`: пример «2026-09-30.xlsx», файл `RPT-2026-09-30.xlsx`.
Причина: пример брал только `entry.projectKey`. Исправление `8b78f25` (`entryProject` из JQL/ключей).

### D2 — выбранные в новом поиске задачи не попадают в выгрузку (важный; платформа)
Шаги: Filters → Search work items («All work», новый навигатор), `project = RPT`, отметить 3 задачи → Apps →
«Export to Excel, Word or PDF». Ожидание: источник — 3 задачи (T7a). Факт: весь поиск, 10 006.
Диагностика (3.4.0, консоль iframe): `issueKeys:array(0)`, `jira:object{isNewNavigation}` — Jira передаёт пустой
список. Код 3.4.0 читает все известные поля выбора; исправить в приложении нельзя (см. ECO-806). → **Ruling R30.**

### D3 — сохранённый фильтр не распознаётся (важный) — исправлен в 3.4.0
`issues/?filter=10034` → действие: источник показывал только JQL, `{filter}` пустой. Причина: `filterId` не читался.
Исправление `8b78f25`: имя фильтра через `GET /rest/api/3/filter/{id}` (scopes не менялись).

### D4 — заголовок «Untitled» в Word/PDF при нескольких задачах (мелкий)
W1, W7, P4: `dc:title`/Title = «Untitled», в PDF со 2-й страницы колонтитул «Untitled». Ожидание: JQL/имя фильтра/источника.

### D5 — пустая полоска на разрыве строки таблицы в PDF «Sprint report» (мелкий)
P1: внизу стр. 1 и 2 под последней строкой — пустой фрагмент строки. Данные не теряются.

### D6 — ошибочный JQL показывается как «ничего не найдено» (важный)
Глобальная страница, `project = RPT AND foo = bar` → ошибки под полем нет; Export → «No issues match this query.»
Причина (проверено на сайте): `POST /rest/api/3/search/approximate-count` отвечает `200 {"count":0}` и на
неизвестное поле, и на пустой результат; приложение не проверяет JQL отдельно. Исправлено в 3.5.0 (`1a12f13`): при пустом результате JQL проверяется `POST /rest/api/3/jql/parse?validation=strict`
(scope `read:jira-work`, манифест не менялся); перепроверено владельцем в браузере.
