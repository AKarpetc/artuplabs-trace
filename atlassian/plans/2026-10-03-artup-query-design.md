# ArtUp Query v1 — спецификация

Дата: 2026-10-03. Основание — бриф [../25_app5_jql.md](../25_app5_jql.md) (§4 планка качества, §5 границы,
§6 архитектура, §11 результаты фазы 0 и выводы прототипа). Решения, принятые без владельца, —
[2026-10-03-artup-query-v1-rulings.md](2026-10-03-artup-query-v1-rulings.md). Следующий документ — план
`2026-10-03-artup-query-v1.md`.

## 1. Что строим

JQL-функции для Jira Cloud, которых нет в родном JQL: по результату другого запроса, по иерархии, по связям,
по истории спринтов, по комментариям, вложениям и сравнению полей. Результат свежий через секунды после
изменения задачи, полный при любом размере, в задачи клиента приложение ничего не пишет. Только Forge,
ноль egress, Runs on Atlassian. Ключ `com.artuplabs.query`, код — `apps/query`, коммиты `JQL-<n>: <Description>`.

Решения владельца (брейншторм 2026-10-03):

| Вопрос | Решение |
|---|---|
| Охват v1 | **максимальный охват рынка**: все группы функций, которые продают лидеры и которых нет в родном JQL; история спринтов — в v1 |
| Имена функций | как в ScriptRunner Data Center: имена и порядок аргументов — фильтры мигрантов с DC работают без правок |
| Архитектура | вариант A: precomputation + обновление по событиям, свои данные — в Forge (KVS + SQL), в задачи не пишем |
| Остальные вопросы | «реши сам» — решения записаны в rulings |

Охват — не только функции: все продукты Jira, где есть JQL (Software, Service Management, Work Management,
Product Discovery), company- и team-managed проекты, 26 языков интерфейса, ≤ 10 пользователей бесплатно.

## 2. Каталог функций v1

Аргумент `subquery` — любой JQL, включая `filter = …` и функции приложения (вложенность). Все функции
поддерживают операторы `in` и `not in`. Этап — порядок постройки (§9), не отдельный релиз.

### M1 — по запросу (проверено прототипом J-G5)

| Функция | Возвращает |
|---|---|
| `subtasksOf(subquery)` | подзадачи задач запроса |
| `parentsOf(subquery)` | родителей задач запроса (подзадача → задача, задача → эпик, любой уровень иерархии) |
| `epicsOf(subquery)` | эпики задач запроса (уровень 1 иерархии) |
| `issuesInEpics(subquery)` | задачи эпиков из запроса, company- и team-managed |
| `childIssuesOf(subquery, [depth])` | все потомки по иерархии (как `portfolioChildIssuesOf`, но по запросу); depth по умолчанию — все уровни |
| `linkedIssuesOf(subquery, [linkType])` | связанные с задачами запроса; linkType — имя типа или направления (`"blocks"`, `"is blocked by"`) |
| `linkedIssuesOfRecursive(subquery, [linkType])` | транзитивное замыкание связей; защита от циклов, предел — 10 уровней |
| `linkedIssuesOfRecursiveLimited(subquery, depth, [linkType])` | то же с заданной глубиной |

### M2 — индекс сайта: связи, иерархия без запроса, история спринтов (ворота J-G6)

| Функция | Возвращает |
|---|---|
| `hasLinks([linkType])` | задачи, у которых есть связи (данного типа) |
| `hasLinkType(linkType)` | синоним `hasLinks(linkType)` (имя ScriptRunner) |
| `hasSubtasks()` | задачи с подзадачами |
| `addedAfterSprintStart(board, [sprint])` | добавлены в спринт после его старта (и если позже убраны); без sprint — активный спринт доски |
| `removedAfterSprintStart(board, [sprint])` | убраны из спринта после старта |
| `incompleteInSprint(board, sprint)` | были в спринте на момент закрытия и не в категории Done |
| `completeInSprint(board, sprint)` | были в спринте на момент закрытия и в Done |
| `previousSprint(board)` / `nextSprint(board)` | задачи последнего закрытого / следующего будущего спринта доски |

board — имя или id доски; sprint — имя или id.

### M3 — комментарии, вложения, поля (ворота J-G7)

| Функция | Возвращает |
|---|---|
| `commented(clauses)` | задачи с комментариями по условиям: `by <user>`, `after <date>`, `before <date>`, `on <date>`, `inRole <role>`, `inGroup <group>`; даты — абсолютные и `-7d`, `startOfWeek()` |
| `lastComment(clauses)` | те же условия, но только к последнему комментарию задачи |
| `hasComments([n])` | задачи с ≥ n комментариями (n = 1 по умолчанию) |
| `fileAttached(clauses)` | вложения по условиям: `by`, `after`, `before`, `ext <xlsx>` |
| `hasAttachments([ext])` | задачи с вложениями (данного расширения) |
| `dateCompare(subquery, "f1 op f2[ ± interval]")` | задачи запроса, где одно поле-дата относится к другому: `resolutiondate > duedate`, `created + 2d < firstCommented` |
| `expression(subquery, "выражение")` | задачи запроса, где арифметика полей-чисел и длительностей истинна: `timespent > originalestimate * 1.2` |

Текст комментариев не хранится и не ищется — только автор, даты, роль/группа видимости (§4).

### Не входит в v1

Поиск по тексту комментариев и вложений; ворклоги (родные `worklogAuthor`/`worklogDate` закрывают основное);
версии и компоненты (родные функции); `lastUpdated(by)`; функции ScriptRunner про скрипты и Groovy;
Jira Data Center.

## 3. Архитектура

Модули Forge:

| Модуль | Что делает |
|---|---|
| `jira:jqlFunction` × каждая функция §2 | вычисляет значение precomputation; аргумент-режим страницы скрыт (`mode` из прототипа) |
| `trigger` — события задач, связей, комментариев, вложений, спринтов | пишет запись журнала (ключ на событие) и ставит задачу в очередь, если её нет |
| `consumer` `refresh` | пересчитывает затронутые precomputation, повторяет себя, пока журнал не пуст (бюджет 240 с на проход) |
| `consumer` `backfill` | первичное заполнение индекса сайта (M2, M3) порциями, с курсором, возобновляемо |
| `scheduledTrigger` раз в час | сверка: пересчёт precomputation с `used` за 24 ч, которые давно не обновлялись; добивка пропусков индекса |
| `jira:globalPage` | справочник функций с примерами и копированием, состояние индекса и очереди, ошибки, лицензия |
| `jira:adminPage` | переиндексация по проекту, исключение проектов, сброс |

Данные (всё в Forge, ничего в задачах клиента):

| Хранилище | Что |
|---|---|
| KVS `t:<ts>:<rand>` | журнал затронутых задач (одна запись на событие — без гонки, найдено в J-G5) |
| KVS `v:<pcId>:<chunk>` | кэш значений precomputation порциями по 5 000 (для страниц дерева) |
| Forge SQL `issue_node` | id, проект, родитель, тип-уровень иерархии, категория статуса — для M2 |
| Forge SQL `issue_link` | источник, цель, тип, направление — для M2 |
| Forge SQL `sprint`, `sprint_event` | спринты (доска, старт, закрытие) и события «добавлена/убрана» с временем и id записи changelog (уникальный ключ — повтор безопасен) |
| Forge SQL `status_event` | смена категории статуса с временем — для `complete/incompleteInSprint` |
| Forge SQL `comment_meta`, `attachment_meta` | автор, created/updated, видимость; имя файла и расширение — без содержимого |

Порядок вычисления функции:

1. Разобрать аргументы (чистые функции `core/args`): ошибка → `{ error }`, Jira показывает её в редакторе JQL.
2. Внутренний запрос — `asApp` `search/jql` (id по 5 000) + `bulkfetch` по 100, 8 параллельно (образец прототипа);
   функции M2/M3 — запрос к SQL-индексу.
3. Значения ≤ 1 000 → `id in (…)`. Больше — дерево: корень из вызовов страниц `issue in fn(…, "tree:k")`,
   страница — до 1 000 id (проверено на 24 000; плоский список и OR списков Jira отвергает с 400).
4. Значения в KVS, чтобы страницы читали только свою порцию.

Права: внутренний запрос и индекс считаются от имени приложения; итог Jira фильтрует по правам
пользователя при поиске — он не увидит задач, которых не видит. Precomputation общий для всех
пользователей — как у родных функций и ScriptRunner Cloud (Ruling Q-R3).

## 4. Данные и приватность

- В индексе — только идентификаторы, связи, типы, категории статусов, даты, авторы (account id). Текст задач,
  комментариев и вложений не хранится.
- Удаление приложения удаляет KVS и SQL (Forge). Удаление задачи/комментария → событие → удаление строки.
- Исключённые проекты (админ-страница) не индексируются; функции по ним возвращают пустой результат с пояснением.

## 5. Свежесть и обновление

- Событие → журнал → `refresh`: какие precomputation затронуты — по пересечению затронутых id с кэшем
  значений и внутренних запросов; если сомнение (журнал ≥ 100 записей, неизвестное событие) — пересчитать все
  активные (`used` за 7 дней).
- Обещание в листинге: **«секунды для обычных правок»**; при массовых правках (импорт, bulk edit) — очередь
  Forge, задержка до минут (замер при досеве: 45–97 событий/мин, до ~275 с).
- Сверка раз в час — страховка от потерянного события.
- Первичное заполнение (M2/M3): при установке и по кнопке; прогресс на странице приложения; функции,
  которым индекс ещё не готов, возвращают ошибку «Индекс строится: N из M» — не пустой результат.

## 6. Ошибки

| Ситуация | Что видит пользователь в JQL-редакторе |
|---|---|
| неверный JQL в subquery | текст ошибки Jira по subquery |
| нет доски/спринта/пользователя/типа связи | «Board "X" not found» и т. п. (26 языков на странице, в редакторе — английский: Jira не передаёт локаль) |
| индекс строится | «Index is building: 12 400 of 50 000 issues» |
| нет лицензии (> 10 пользователей) | «ArtUp Query license is not active» |
| превышен бюджет вычисления (25 с) | вычисление продолжается в очереди; «Computing, retry in a minute» — не пустой и не частичный результат |

## 7. Лицензия и цена

≤ 10 пользователей — бесплатно (`license` в контексте функции и страниц). Цена листинга — **$175/мес за 200**
(бриф §2; J-G3 — не снижать).

## 8. Тесты и приёмка

- Ядро — чистые функции (`core/args`, `core/jql-build`, `core/tree`, `core/affected`, `core/sprint-history`,
  `core/comment-clauses`, `core/expression`), vitest, покрытие ветвлений.
- Приёмка на `artuplabs-dev`, проект JQLG (50 000 задач) — каждая строка §4 брифа:
  - полнота 100% против эталона REST для каждой функции §2 на данных > 1 000 и > 10 000;
  - свежесть p90 ≤ 60 с по 30 изменений на группу; **0 потерянных обновлений на 150 изменениях**;
  - всплеск 200 изменений/мин — замер инструментом с таймаутом запросов и повтором сетевых ошибок (сломалось в J-G5);
  - понятные ошибки по §6; ничего не пишется в задачи (проверка аудита задач после прогона);
  - сравнение с ScriptRunner: 20 фильтров-образцов из документации ScriptRunner дают тот же смысл.
- Ручная приёмка владельцем — чек-лист по образцу Reports.

## 9. Этапы постройки и ворота

| Этап | Содержание | Ворота до кода этапа (записаны до замера) |
|---|---|---|
| M1 | каркас, лицензия, страница, функции по запросу, журнал | J-G5 пройден; первая задача — 0 потерь на 150 изменениях на версии с журналом |
| M2 | индекс сайта, история спринтов | **J-G6**: заполнение индекса (узлы, связи, changelog Sprint+status через `POST /rest/api/3/changelog/bulkfetch`) на 50 000 задач ≤ 60 мин; событие → функция спринта p90 ≤ 60 с; `addedAfterSprintStart` на 30 спринтах совпадает с эталоном, восстановленным из changelog вручную, на 100%. Не прошло — группа уходит в v1.1 (Ruling), остальное идёт |
| M3 | комментарии, вложения, сравнение полей | **J-G7**: заполнение метаданных комментариев и вложений на 50 000 задач (6 000+ комментариев) ≤ 60 мин; p90 ≤ 60 с; полнота 100%. Не прошло — группа в v1.1 |
| M4 | приёмка §8, листинг, сайт | все строки §4 брифа |

Листинг подаётся один раз — после M4.

## 10. Первые проверки плана

1. Сверить имена и сигнатуры §2 с документацией ScriptRunner (DC и Cloud) — расхождения в rulings.
2. Версия прототипа с журналом: 0 потерь на 150 изменениях (иначе — отладка до M1).
3. Наличие и лимиты `changelog/bulkfetch` и событий спринтов (`avi:jira-software:*:sprint`) в Forge.
