## Шаг 0. Подготовка (до браузера)

1. `git status` чистый, ветка `reports-v1`. `cd apps/reports && forge logs -e development --since 1h` — запомнить, что лог пуст до начала.
2. Создать `apps/reports/data/browser-test/inbox/` и `.../shots/` (скриншоты браузера).
3. Написать `apps/reports/scripts/verify-download.mjs` (Opus-субагент, если пишешь не сам; без тестов — это инструмент приёмки), который принимает `--file <путь> --case <ID> [--expect-issues N] [--jql "..."]` и печатает JSON-отчёт + строку `PASS`/`FAIL` с причинами. Проверки — в разделе «Проверка скачанных файлов». Прогнать его на файлах из `apps/reports/data/` (остались от приёмки в Node), чтобы убедиться, что он работает до браузера.
4. **Засеять особые задачи** в RPT через REST (basic auth из `.env`), каждой метку `browser-test`:
   - `BT-FILECARD`: описание со вставленной карточкой файла **PDF** (вложение `spec.pdf`, медиа-узел в ADF) и одной PNG-картинкой — проверка R26 (не-картинка пишется именем файла, не скачивается, нет предупреждения «нет изображения»);
   - `BT-PHONEJPEG`: JPEG с хвостом после маркера конца (обычный JPEG + дописанные в конец байты, как у Samsung/Pixel) во вложении и в описании — проверка R29 (картинка есть в PDF и в своём шаблоне Word);
   - `BT-EMPTY`: задача без описания, без исполнителя, без срока — пустые поля не ломают файлы.
   Записать ключи созданных задач в файл итогов. Ничего другое в RPT не менять и не удалять.

## Проверка скачанных файлов (что делает `verify-download.mjs`)

Общее для всех: файл открывается библиотекой без ошибок; имя совпадает с шаблоном имени (по умолчанию `DEFAULT_FILE_PATTERN` из `static/app/src/core/limits.js`/`filename.js`), `-PARTIAL` только у частичных; размер > 0.

- **xlsx (ExcelJS):** листы и их имена; число строк данных (без шапки) = `--expect-issues` (для worklogs/comments — число записей); гиперссылок в колонке ключа = числу строк, ссылки ведут на `https://artuplabs-dev.atlassian.net/browse/<KEY>`; типы ячеек дат — Date; закрепление (`views[0].state === 'frozen'`, `ySplit ≥ 1`); `autoFilter` на шапке; лист сводки: JQL, время, автор, число; `workbook.description` содержит JQL и число задач (R28); нет строк длиннее 32 767 символов; нет формул из текста задач (текст начинается с `=` хранится как строка).
- **docx (PizZip + XML):** нет `{{` ни в одной части; `word/media/*` — число картинок, все — PNG/JPEG/GIF по сигнатуре, нет `.pdf`/`.zip` (R26); `w:tblHeader` у таблиц; поля `PAGE`/`NUMPAGES` в колонтитуле; размер страницы (`w:pgSz`) A4 11906×16838 или Letter 12240×15840; в `document.xml` есть ключи ожидаемых задач; частичный файл содержит текст баннера частичности; `word/_rels/document.xml.rels` — у каждой картинки есть связь.
- **pdf (pdfjs-dist):** число страниц; размер страницы A4 (595×842) или Letter (612×792); текст содержит ключи задач и заголовок отчёта; для CJK-случаев — есть символы CJK (`/[぀-ヿ一-鿿가-힯]/`); `pdftoppm -r 80 -png -f 1 -l 3` → PNG в `data/browser-test/inbox/<ID>-pages/`, затем **посмотри глазами** (Read по PNG): нет квадратиков вместо знаков, текст и таблицы в пределах полей.
- **Что сравнить с экраном:** число задач в файле = «задач» на экране результата; число картинок в файле ≈ «картинок» минус «нет изображений».
- Вывод: JSON (все цифры) + `PASS`/`FAIL: <причины>`; JSON сохранить рядом с файлом (`<имя>.verify.json`) и сослаться на него в итогах.
