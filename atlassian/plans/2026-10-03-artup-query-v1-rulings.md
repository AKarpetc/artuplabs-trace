# ArtUp Query v1 — решения без владельца (rulings)

Владелец 2026-10-03: «реши все вопросы сам», «делаем на максимальный обхват рынка». Здесь — решения,
принятые по этому слову; владелец может отменить любое.

| # | Решение | Почему |
|---|---|---|
| Q-R1 | v1 = четыре этапа M1–M4 в одной ветке и одном листинге; группа функций, не прошедшая свои ворота (J-G6, J-G7), уходит в v1.1, а не останавливает приложение | максимальный охват без риска, что непроверенная часть задержит проверенную |
| Q-R2 | в каталог v1 добавлены `childIssuesOf`, `linkedIssuesOfRecursive(Limited)`, `hasLinks`/`hasLinkType`, `hasSubtasks`, `previousSprint`/`nextSprint`, комментарии, вложения, `dateCompare`, `expression` | основные группы функций лидеров (JQL Search Extensions, ScriptRunner, Enhanced Search), которых нет в родном JQL |
| Q-R3 | precomputation и внутренние запросы — от имени приложения; итог фильтрует Jira по правам пользователя | precomputation общий для всех пользователей по устройству Forge; так же работают ScriptRunner Cloud и родные функции |
| Q-R4 | текст комментариев и вложений не хранится и не ищется | приватность и Runs on Atlassian; поиск по тексту — родной `text ~` |
| Q-R5 | в листинге обещаем «секунды для обычных правок», про массовые правки — честно «до минут» | замер досева: очередь Forge 45–97 событий/мин, задержка до ~275 с |
| Q-R6 | ошибки в редакторе JQL — на английском; страница приложения — 26 языков | Jira не передаёт локаль в вычисление функции |
| Q-R7 | ворклоги, версии, компоненты — вне v1 | закрыты родными функциями |
| Q-R8 | цена $175/мес за 200, ≤ 10 бесплатно | бриф §2, J-G3 |
| Q-R9 | `hasLinks`/`hasLinkType` → родной `issueLinkType …`; `hasSubtasks` → живой поиск подзадач и их родителей; `previousSprint`/`nextSprint` → родной `sprint = <id>` через Agile API. Эти функции не требуют индекса: строятся в M1 и остаются в v1 при любом исходе J-G6. Таблицы `issue_node`/`issue_link` не строятся — иерархия и связи читаются живыми запросами; J-G6 меряет то, что строится (changelog Sprint+status), порог не меняется | меньше индекса — меньше рисков свежести и полноты; родной JQL всегда свеж и без предела 1 000 |
| Q-R10 | страница дерева — скрытый последний аргумент `__aq:l<n>` (лист) / `__aq:m<n>` (узел); до замера — 1 уровень (≤ 9 000 значений), 2 уровня (≤ 81 000) включаются только после проверки на сайте (Task 30); сверх ёмкости — явная ошибка с числами | прототип доказал 1 уровень (9 листьев), 2 уровня не мерялись |
| Q-R11 | если J-G7 не пройдён, в v1.1 уходят только функции на индексе комментариев/вложений (`commented`, `lastComment`, `hasComments`, `fileAttached`, `hasAttachments(ext)`); `dateCompare`/`expression` индекса не требуют и остаются (без псевдополей `firstCommented`/`lastCommented`); `hasAttachments()` без аргумента — родной `attachments is not EMPTY` | Q-R1: непроверенная часть не задерживает проверенную |
| Q-R12 | даты в условиях (`after`, `on`, `-7d`, `startOfWeek()`) — UTC, неделя с понедельника; длительности в `expression`: 1d = 8h, 1w = 5d (умолчание Jira) | Jira не передаёт в функцию ни часовой пояс пользователя, ни настройки учёта времени (их чтение требует прав администратора) |
| Q-R13 | исключение проектов (админ-страница) действует на индекс (M2/M3); функции M1 читают живые данные и проектом не ограничены; функция спринта на доске исключённого проекта отвечает ошибкой «Project X is excluded…» | спецификация §4 требует пояснения, а не тихого пустого результата |
| Q-R14 | журнал ошибок страницы хранит имя функции и текст ошибки, но не аргументы (в них JQL клиента) | приватность (§4 спецификации) |
| Q-R15 | `currentUser()` внутри аргументов отклоняется явной ошибкой | precomputation общий для всех пользователей (Q-R3), внутренний запрос идёт от имени приложения |
| Q-R16 | в приложении вызов `issue in имя(…)`, а не `issueFunction in имя(…)`; мигрант со ScriptRunner меняет одно слово, остальной JQL и имена функций те же; страница приложения это объясняет | Forge `jira:jqlFunction` вызывается как `issue in <функция>`; у ScriptRunner Cloud функции работают только на экране Enhanced Search, у нас — в обычном поиске, фильтрах и на досках (`docs/scriptrunner.md`) |
| Q-R17 | `hasComments()` — любые комментарии; `hasComments(n)` — как в ScriptRunner: число = ровно n, `'+n'` = больше n, `'-n'` = меньше n (в §2 было «≥ n»); поправить каталог (Task 5) и ожидания тестов Task 25 при исполнении | DC: «`hasComments(3)` … exactly three comments», «`hasComments('+5')` … more than five», «`hasComments('-3')` … less than three» (https://docs.adaptavist.com/sr4js/latest/features/jql-functions/included-jql-functions/comments); молчаливое расхождение смысла у мигрантов хуже, чем отступление от §2 |
| Q-R18 | `hasAttachments([ext])` — второй аргумент ScriptRunner (число вложений со знаком) в v1 не поддержан, вызов с ним даёт явную ошибку | DC: `hasAttachments([file extension], [number of attachments])` (https://docs.adaptavist.com/sr4js/latest/features/jql-functions/included-jql-functions/attachments); счётчик не входит в §2 и в замеры J-G7, ошибка честнее тихого игнорирования |
| Q-R19 | `hasLinks([linkType])` и `hasLinkType(linkType)` принимают и имя типа (`Blocks`), и описание направления (`blocks`, `is blocked by`); число связей вторым аргументом (`hasLinks("blocks", "+2")`) — не в v1, явная ошибка | DC различает: `hasLinks` — описание направления («for the outward or inward link description»), `hasLinkType` — имя типа «in either direction» (https://docs.adaptavist.com/sr4js/latest/features/jql-functions/included-jql-functions/issue-links); §2 уже называет их синонимами, принимать оба вида строго шире ScriptRunner |
| Q-R20 | `linkedIssuesOfRecursive(Limited)` включает задачи подзапроса только если они достижимы по связи (допущение плана подтверждено) | DC: «SSP-1 is returned as it is linked to SSP-2 and SSP-3» — задача подзапроса вернулась из-за достижимости (https://docs.adaptavist.com/sr4js/latest/features/jql-functions/included-jql-functions/issue-links); расхождения с планом нет |
| Q-R21 | `removedAfterSprintStart`: «убраны» = убраны после старта и не возвращены до закрытия спринта (допущение плана сохраняется) | документация DC молчит про убранные и вновь возвращённые («Show issues that were removed from the named board after the named sprint started», https://docs.adaptavist.com/sr4js/latest/features/jql-functions/included-jql-functions/sprint); выбран смысл, который совпадает с итоговым составом спринта |
| Q-R22 | (P-8) как в ScriptRunner DC: `commented()`/`lastComment()` без условий = любой комментарий; `inRole`/`inGroup` = автор комментария состоит в роли/группе; `roleLevel`/`groupLevel` = видимость комментария; у `fileAttached` условие `on` сохраняется, `ext` — наше добавление; `visibility` (JSM) не в v1 | DC: «Do not confuse `roleLevel` and `inRole`. `roleLevel` is the security level applied to a comment, `inRole` refers to the role(s) of the person making the comment» (https://docs.adaptavist.com/sr4js/latest/features/jql-functions/included-jql-functions/comments); у `fileAttached` предикаты `by`, `after`, `before`, `on` (https://docs.adaptavist.com/sr4js/latest/features/jql-functions/included-jql-functions/attachments); поведение `commented()` без условий документация не описывает, берём естественное (любой комментарий) — допущение плана; в Cloud `inRole`/`inGroup` не поддержаны, у нас поддержаны |
| Q-R23 | `dateCompare`: операторы `<`, `>`, `<=`, `>=`, `=`; интервал `+Nw`/`+Nd` (и `-`) у любого поля слева и справа, псевдополя `firstCommented`/`lastCommented`; `.clearTime()` (Cloud) — не в v1 | DC: «Supported Operators: `<`, `>`, `<=`, `>=`, `=`», «Time Interval Syntax: `+2w`, `+1w`, `+2d`», поля `firstCommented`/`lastCommented` (https://docs.adaptavist.com/sr4js/latest/features/jql-functions/included-jql-functions/date); `.clearTime()` появляется только на странице Cloud |
| Q-R24 | `expression`: единицы `Nw/Nd/Nh/Nm` по Q-R12 (1d = 8h, 1w = 5d), плюс псевдонимы ScriptRunner `wd` (= 8h) и `ww` (= 5wd), чтобы `5*wd` работало без правки; сравнения `>`, `<`, `>=`, `<=`, `=`, `==`, `!=`; поля с пробелами — без пробелов или `customfield_NNNNN` | DC: «`wd` — working day (based on your time tracking configuration)», «`ww` — working week», «`d` — 24-hour day (for non-time-tracking comparisons)»; «Use `5*wd` rather than `5d`» (https://docs.adaptavist.com/sr4js/latest/features/jql-functions/included-jql-functions/calculations); у ScriptRunner `d` = 24 ч, у нас по Q-R12 8 ч (настройки времени недоступны) — расхождение записано в справочнике функций |
| Q-R25 | имя иерархической функции — `childIssuesOf(subquery, [depth])` без алиасов `childrenOf` (Cloud) и `portfolioChildrenOf` (DC, только Advanced Roadmaps); `parentsOf` второго аргумента глубины (Cloud) не получает | имена не совпадают в трёх продуктах; алиас — лишний вход в манифесте на каждое имя, §2 уже описывает функцию как «как `portfolioChildrenOf`, но по запросу» (https://docs.adaptavist.com/sr4jc/latest/features/scriptrunner-enhanced-search/scriptrunner-enhanced-search-jql-functions/links-and-relationships/) |
| Q-R26 | `incompleteInSprint(board, sprint)` и `completeInSprint(board, sprint)` — sprint обязателен (у DC необязателен: «or all active sprints if a second argument is not provided»); `addedAfterSprintStart`/`removedAfterSprintStart` без sprint — активный спринт доски, как в §2 | §2: «были в спринте на момент закрытия»; для активных спринтов состав «закрытия» не определён (https://docs.adaptavist.com/sr4js/latest/features/jql-functions/included-jql-functions/sprint) |
| Q-R27 | (P-1) вердикт полноты J-G6 — 30 из 30 `complete` против эталона B (changelog по REST); сравнение засева A с B — проверка сеялки: расхождение означает починку засева или инструмента и повтор замера, а не «не пройдено» | порог §9 спецификации не меняется |
| Q-R28 | (P-2) J-G7 меряет и вложения (фазы `attachment-latency`, `attachment-complete`); если не проходят только вложения, в v1.1 уходят только `fileAttached` и `hasAttachments(ext)` (Q-R11) | §9: «метаданные комментариев **и вложений**» |
| Q-R29 | (P-3) размер случая полноты для каждой функции — максимальный, какой дают данные; функции спринта — плюс один спринт на 1 000+ задач из `jg-task`; `hasComments("1")`, `commented("after 2020-01-01")`, `hasAttachments()` — на всём сайте; документ приёмки пишет фактический размер каждого случая | §8: полнота «на данных > 1 000 и > 10 000» |
| Q-R30 | (P-4) 25 с — предел платформы на ответ функции; внутренний бюджет вычисления — `FUNCTION_BUDGET_MS = 20 000`, чтобы успеть записать очередь, `q:jobs` и журнал ошибок; поведение по §6 («Computing, retry in a minute») не меняется | запас на запись состояния до предела платформы |
| Q-R31 | (P-5) кэш значений — по группе: `v:<sha1(groupKey)>:{m,c<i>,w<i>}` вместо `v:<pcId>:<chunk>` §3 | страницы дерева читают набор значений корня (Review Focus 2); `w<i>` — список отслеживаемых id, по нему решается, что пересчитывать (§5) |
| Q-R32 | (P-6) эталоны приёмки (`scripts/lib/reference.mjs`) и инструменты замера (`atlassian/tools/*`, `scripts/lib/http.mjs`, `scripts/lib/latency.mjs`) намеренно не импортируют `src/` и держат свои копии `pool`, разбора условий и вычисления выражений | эталон, собранный из кода продукта, не поймает ошибку продукта |
| Q-R33 | (P-7) покрытие ветвлений §8 — порог: `npm run coverage` (`@vitest/coverage-v8`), ветви `src/core/**` ≥ 90% | §8: «vitest, покрытие ветвлений» |
| Q-R34 | `linkedIssuesOf(subquery, [linkType])` принимает один необязательный linkType (имя типа или направления); несколько имён связей, как у ScriptRunner DC, — явная ошибка с подсказкой вызвать функцию дважды и объединить через OR | DC: `linkedIssuesOf("subquery", "link name"[, "link name"…])`, пример `linkedIssuesOf("","is blocked by", "is cloned by")` (https://docs.adaptavist.com/sr4js/latest/features/jql-functions/included-jql-functions/issue-links); §2 и Cloud (`linkedIssuesOf(Subquery, [link type])`, https://docs.adaptavist.com/sr4jc/latest/features/scriptrunner-enhanced-search/scriptrunner-enhanced-search-jql-functions/links-and-relationships/) берут один тип; явная ошибка честнее тихого игнорирования лишних аргументов |
| Q-R35 | `addedAfterSprintStart(board, [sprint])` и `removedAfterSprintStart(board, [sprint])` без sprint — активный спринт доски (как в §2), а не «все активные спринты», как у ScriptRunner DC | DC: «(or all active sprints if a second argument is not provided)» (https://docs.adaptavist.com/sr4js/latest/features/jql-functions/included-jql-functions/sprint); у доски обычно один активный спринт, а запись «активный спринт доски» — как в §2 и в Cloud (`addedAfterSprintStart(Board, [Sprint])`); при нескольких активных спринтах на доске результат у мигранта может отличаться — пояснение в справочнике функций |
| Q-R36 | `hasLinks`/`hasLinkType`: аргумент, равный (без учёта регистра) ИМЕНИ типа связи, означает обе стороны → нативный `issueLinkType`; аргумент, равный описанию направления (outward/inward), — только это направление → нативный `issueLinkType` лишь когда описание не совпадает без учёта регистра ни с одним именем типа, иначе вычисляемый список id (дерево) | живая проверка (`apps/query/docs/live-checks.md`): `issueLinkType = "blocks"` вернул 1 863 задач (обе стороны) против эталона 1 190 по outward; Cloners, Duplicate, Relates совпали точно |
| Q-R37 | старт спринта = `startDate`; Agile API сайта не возвращает `activatedDate` (проверено на future/active спринтах; closed не проверены до засева) | `apps/query/docs/live-checks.md`, раздел «Agile sprints»; OpenAPI спринта тоже без `activatedDate` |
| Q-R38 | в документации Forge нет события `avi:jira:updated:comment`: правки комментариев подхватывает часовая сверка; листинг не обещает секунды для правок комментариев (формулировка — Task 27) | https://developer.atlassian.com/platform/forge/events-reference/jira/ — описаны только `avi:jira:commented:issue`, `avi:jira:mentioned:comment`, `avi:jira:deleted:comment` |
| Q-R39 | идемпотентность обработки событий не зависит от `changelog.id`; запасной ключ — `issue.id` + `timestamp` + содержимое `items` | https://developer.atlassian.com/platform/forge/events-reference/jira/ — `changelog` описан как «A list of changes that have occurred in the update», поле `id` не документировано; `timestamp` в примерах тоже не показан, поэтому при его отсутствии ключ строится по `issue.id` + `items` и времени получения |
