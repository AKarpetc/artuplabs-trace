## 5. Границы v1

### Входит

1. **Точки входа:** меню приложений на странице поиска (`jira:issueNavigatorAction`), доска,
   бэклог и спринт (`jira:boardAction`, `jira:backlogAction`, `jira:sprintAction`), одна задача
   (`jira:issueAction`), своя страница с выбором фильтра/JQL (`jira:globalPage`).
2. **Excel (.xlsx):** колонки — любые поля, включая custom fields, комментарии, ворклоги,
   связи, подзадачи; типы данных; группировка по полю на листы; лист «Сводка» (счёт по статусу,
   исполнителю, приоритету).
3. **Word (.docx):** шаблон пользователя с плейсхолдерами + 4 встроенных (одна задача, список,
   отчёт по спринту, релиз); картинки, таблицы, форматирование описания (ADF → docx).
4. **PDF:** те же 4 шаблона; шрифты латиница, кириллица, CJK в бандле.
5. **Хранилище шаблонов** — Forge KVS/SQL, доступ по проекту; только метаданные шаблонов,
   не содержимое задач.
6. Лицензия: ≤ 10 пользователей бесплатно; `license.active` в резолвере и во фронте.
7. 26 языков интерфейса, светлая/тёмная тема — как в Trace и Export.

### Не входит в v1

- Экспорт по расписанию и рассылка по почте — нужен сервер или egress (v1.1: расписание через
  Forge scheduled trigger с вложением файла в задачу — без egress, проверить отдельно).
- Импорт из Excel обратно в Jira.
- Jira Data Center; PowerPoint; PDF/A.

## 6. Архитектура: сборка в браузере

Решение ArtUp Export (вариант A, пройден на 1 000 страницах) переносится:

- Custom UI запрашивает задачи через `requestJira` из `@forge/bridge` от имени пользователя:
  `POST /rest/api/3/search/jql` с `nextPageToken`, поля по шаблону, `expand=renderedFields`
  только для Word/PDF; комментарии и ворклоги — отдельными запросами пачками, конкурентность
  как в Export (6), повтор на 429.
- Сборка файла — в браузере, библиотеками в бандле (выбраны по X-G5): .xlsx — `exceljs` (MIT;
  SheetJS CE не пишет стили); .docx — `docx` (MIT); PDF — `pdfmake` (MIT) со статическими шрифтами
  Noto и разбивкой текста по письменности. Чтение — id по 5 000, затем `bulkfetch` по 100
  параллельно; вложения — конкурентность ≥ 12 (§11). Скачивание — Blob + `<a download>`, «Скачать ещё раз», как в Export.
- Ядро — **чистые функции без I/O**: планировщик полей, ADF → docx/pdf-модель, форматтеры
  типов, подстановка плейсхолдеров, имя файла. Хендлеры тонкие.
- Лимиты Forge (резолвер 25 с, ответ 5 МБ) не касаются сборки: резолвер только отдаёт
  шаблоны и лицензию.

### Что прототип выяснил для плана

1. **Порядок чтения:** id страницами по 5 000, затем `bulkfetch` по 100 параллельно — в 5 раз быстрее последовательного поиска.
2. **Шрифты PDF:** смешанный текст давал «тофу» — нужна разбивка текста на куски по письменности (латиница/кириллица ↔ CJK) с отдельным шрифтом на кусок; вариативные шрифты не дают жирного — только статические Regular/Bold (Noto Sans 0,6 МБ; Noto Sans SC 8,3 МБ — грузить лениво, только если в выгрузке есть иероглифы; корейский — отдельный Noto Sans KR). Проверено отрисовкой страницы.
3. **Библиотеки:** exceljs 4.4.0 (MIT, стили есть; последний релиз 2024-12, `uuid` с moderate-уязвимостью — закрыть `overrides`); SheetJS CE стилей не пишет — не годится для «форматированного» Excel; docx 9.8.1 и pdfmake 0.3.11 (MIT, свежие); каждый бандл ~1 МБ — грузить по формату.
4. **Память:** пик 766 МБ в Node на 500 задачах с картинками и 55 МБ PDF — в браузере держать картинки потоком и не копить все документы сразу; 50 000 задач в .xlsx — отдельный замер в приёмке.
