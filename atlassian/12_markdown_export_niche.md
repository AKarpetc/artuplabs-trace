# Ниша: экспорт Confluence в Markdown

Дата: 2026-09-15. Разбор конкурента и ответ на вопрос «можем ли сделать
популярное расширение дешевле и лучше».

## Вывод одной строкой

**Лучше — да, и дефекты лидера известны поимённо. Дешевле — нет, и это
противоречит самому сильному измерению в папке.** Цена ниже рынка переводит
приложение в сегмент, где цель берут **2%** листингов вместо **24%**
([09](09_timeline_measured.md) §4.1). Правильный ход — **дороже и лучше**,
а не дешевле.

## 1. Лидер: Markdown Exporter for Confluence

| | |
|---|---|
| Установок | **2 220** |
| Цена | тир 1–10 **$0**, дальше только годовая: 50 мест $250/год, 200 мест **$900/год ($75/мес)**, 1000 мест $3 350/год |
| Обновлён | 2026-09-08, версия 3.5.0 |
| Платформа | **Forge** |
| Отзывов | 22: 5★ — 2, 4★ — 12, 3★ — 4, 2★ — 2, 1★ — 2 |

Средняя оценка около 3.5 при двенадцати четвёрках — это профиль «работает,
но с оговорками», а не профиль любимого продукта.

### Что он умеет

- экспорт одной страницы и **массовый экспорт иерархии** с дочерними;
- изображения и вложения;
- экспорт целого пространства;
- **переписывание ссылок** между страницами и путей к вложениям — это его
  настоящее преимущество, и отзыв это прямо фиксирует: *«Most tools we found
  were able to do this, but only up to a certain point. Mostly links to other
  pages and references to attachments would not work afterwards»*.

### Что он не умеет — из его же отзывов

| Дефект | Отзыв |
|---|---|
| **Не экспортирует внуков** — только один уровень вложенности | *«It doesn't export grandchild pages»* (3★, 2025-03) |
| **Теряет порядок страниц** — дочерние сортируются по алфавиту имени файла, а не по порядку в Confluence | *«the hierarchical order of child pages is not exported… ordered alphabetically by filename»* (4★, 2025-10) |
| **Ломает имена файлов с диакритикой** — ščřžýá вырезаются вместо транслитерации | *«it can't handle diacritics in file names»* (4★, 2025-07) |
| **Медленный на больших объёмах** | *«A bit slow for my 995 page export»* (4★, 2025-10) |

Четыре конкретных, проверяемых, узких дефекта у лидера категории. Это ровно
тот материал, который [10](10_action_list.md) §1 искал и не нашёл в теме
«согласование».

### И сценарий LLM уже происходит сам

*«Flawless markdown export, perfect for editing outside of Confluence or
**sharing with an LLM**»* (4★, 2025-05). Пользователи уже применяют экспорт
для этого, без всякого AI в описании приложения.

## 3. Почему «дешевле» — неверный ход

Самое сильное измерение в папке ([09](09_timeline_measured.md) §4.1): доля
новых листингов, берущих $5 000/мес за три года, зависит от состава клиентов:

| Сегмент | Нужно установок | Взяли порог |
|---|---|---|
| корпоративный (200+ мест) | 111 | **24%** |
| смешанный | 208 | 14% |
| мелкие клиенты | 667 | **2%** |

Markdown Exporter стоит **$75/мес** за 200 мест при медиане рынка **$147**
([04](04_market_measurement.md) §3). Он **уже вдвое дешевле рынка.**

Считаем, сколько нужно клиентов:

| Цена за 200 мест | Клиентов до $5 000 | Установок при 30% платящих |
|---|---|---|
| $50 (дешевле лидера) | 100 | **333** |
| $75 (как лидер) | 67 | 222 |
| $147 (медиана рынка) | 34 | 113 |
| $175 (как Git for Confluence) | 29 | **95** |

Разница между «дешевле лидера» и «как Git for Confluence» — **в 3.5 раза по
числу установок**. У лидера сейчас 2 220 установок, накопленных годами;
новому листингу нужно 95, а не 333.

**Дешевизна не ускоряет, а замедляет.** И она отдаёт единственный рычаг,
который в двенадцать раз сильнее всех остальных.

## 4. Что значит «лучше» конкретно

Четыре дефекта лидера — это цена входа, а не продукт. Починить их
обязательно, но само по себе это даёт «то же самое, но без багов», а такое
не покупают дороже.

**Продукт получается из другой рамки: экспорт, пригодный для git.** Именно
она оправдывает цену выше лидера, потому что нужна инженерной организации,
а не одному человеку — то есть попадает в корпоративный сегмент.

| Что | Зачем | Есть ли у лидера |
|---|---|---|
| Внуки и вся глубина иерархии | без этого пространство не выгружается целиком | **нет** |
| Порядок страниц как в Confluence (числовые префиксы или `_index`) | иначе дерево рассыпается | **нет** |
| Транслитерация имён: диакритика, кириллица, CJK | иначе файлы теряются | **нет** |
| **Стабильные пути между выгрузками** | без этого каждый повторный экспорт даёт мусорный diff — и git-сценарий не работает вообще | нет |
| **Front-matter** с id страницы, автором, датой, метками, пространством | без метаданных выгрузка бесполезна для индексации и LLM | нет |
| **Инкрементальный экспорт** — только изменённые страницы | иначе 995 страниц каждый раз, отсюда же и жалоба на скорость | нет |
| Манифест выгрузки: что, когда, какой версии | аудит и воспроизводимость | нет |
| Переписывание ссылок и вложений | **это надо повторить** — сильная сторона лидера | **да** |

Первые три — починка чужих багов. Строки 4–7 — то, чего нет ни у кого, и
ровно то, что отличает «скачал зип» от «документация живёт в git».

**Расписание не нужно** — по [02](02_forge_implementation.md) §1.1 push в
внешний git требует egress и стоит бейджа. Инкрементальный экспорт по кнопке
со стабильными путями даёт девять десятых пользы без egress: git-операции
делает сам пользователь или его CI.

## 5. Риск, который надо принять осознанно

**Atlassian двигается в эту сторону.** Отзыв 2026-07: *«More powerful and
useful then the 'new' built in Confluence markdown exporter»* — то есть
встроенный экспорт в Markdown в Confluence Cloud уже появился, пусть пока
и для одной страницы.

Это тот же класс риска, что убил рамку «Markdown для LLM»
([11](11_feature_requests.md) §2): платформа или вендор закрывает задачу
бесплатно. Здесь он мягче — массовый экспорт иерархии со стабильными путями
и front-matter Atlassian вряд ли сделает скоро, — но он есть, и он
ограничивает горизонт.

Смягчение: строить на том, что платформе неинтересно (воспроизводимость,
инкрементальность, метаданные для инженерных процессов), а не на том, что
она уже начала делать (экспорт одной страницы).

## 6. Предлагаемое решение

| Параметр | Значение |
|---|---|
| Продукт | экспорт пространства Confluence в Markdown, пригодный для git |
| Egress | **нет** → Runs on Atlassian и 100% ревшары сохраняются |
| Цена 200 мест | **$150–175**, то есть вдвое дороже лидера и на уровне Git for Confluence |
| Тир 1–10 | $0, как у 73% рынка |
| Клиентов до цели | 29–34 |
| Установок до цели | 95–113 при 30% платящих |
| Отличие | глубина, порядок, имена, **стабильность путей, front-matter, инкрементальность** |

Обоснование цены выше лидера: лидер продаёт «скачать зип». Мы продаём
«документация воспроизводимо живёт в git» — это инженерный процесс, за него
платит организация, а не человек.

## 7. Что проверить до кода

1. **Цена $150–175 против $75 у лидера — выдержит ли.** Проверяется чтением
   отзывов Git for Confluence ($175, 1 078 установок): жалуются ли на цену.
2. **Встроенный экспорт Confluence** — выяснить точно, что он уже умеет:
   одна страница или иерархия. Если иерархия — ниша закрывается.
3. **Лимиты Forge на 995 страниц.** Тяжёлая выгрузка идёт в async-очередь
   (до 900 с, [03](03_build_guide.md) §3), но объём zip и память 1 024 МБ
   надо посчитать до архитектуры.
4. Есть ли уже приложение с front-matter и стабильными путями — поиском по
   каталогу, а не по названию (урок из [10](10_action_list.md) §1).
